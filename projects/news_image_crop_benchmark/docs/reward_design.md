# Reward 设计

## 原则

裁剪任务不存在唯一正确的 bbox。Reward 应评价候选裁剪质量，而不是计算候选框与某个目标裁剪框之间的 IoU。

`CroppedImageUrl` 不一定是当前行标题对应的错误裁剪；原始 `Reason` 虽然描述了某次真实裁剪，但无法与该 URL 配对。因此二者都禁止作为 Reward、标签、失败类型、基线或 learned reward model 的训练目标。

语法或几何结构非法时给予固定负奖励。宽高比和图片边界通过确定性几何逻辑强制满足，而不是作为软偏好交给模型学习。

## Proxy Reward 分项

所有分项 adapter 都必须返回 `[0, 1]` 范围内的归一化得分，并暴露原始诊断信息。

### 标题相关性

比较冻结的标题文本 embedding 与候选裁剪图 embedding。既记录绝对相似度，也记录相对完整原图的改善幅度。在新闻领域完成检索质量校准之前，不固定最终 checkpoint。

### 主体完整性

在原图中定位标题实体或通用显著物体。根据候选框保留相关物体 bbox 的加权比例进行评分；如果候选框只与高置信度主体部分相交、造成主体截断，则给予惩罚。

### 显著区域保留

预先计算原图的显著性图，同时根据保留的显著性总量和显著性密度评分。不能只使用保留总量，否则 Reward 会始终偏向保留完整原图。

### 完整性

对原图执行一次人脸和 OCR 检测。完整包含重要区域时给予奖励；裁剪边界切断人脸、logo 或文本行时给予惩罚。

### 构图与美学

构图分评价主体位置、头顶留白和主体与边界的距离。经过领域校准后，可以使用冻结的美学预测器提供低权重得分。这些指标都不能压过语义相关性或完整性。

### 裁剪面积

使用低权重、较宽松的面积先验：实际保留面积在 25% 到 75% 之间时得满分；接近 0% 或 100% 时逐渐降到 0。这样可以防止极小裁剪和不裁剪退化，同时不假设只有一个正确裁剪面积。

## Reward 聚合

初始 proxy 权重位于 `config/benchmark.yaml`，并传给 `combine_proxy_reward`。这些权重只是待校准默认值，不是已经验证的常量。每个分项都必须独立记录，以便发现 reward hacking。

## 防投机检查

- 全图退化：监控动作面积，并强制满足目标宽高比。
- 极小裁剪退化：强制最小有效面积和主体完整性。
- 只保留文字/logo 的退化：联合比较标题相关性、主体和完整性得分。
- 中心裁剪退化：按场景和比例报告裁剪中心直方图。
- 指标过拟合：保持 Reward adapter 冻结，并使用独立人工评价。

## Learned Reward Model

v0 不要求 learned reward model。在积累 proxy 指标和人工比较结果后，可以训练或蒸馏裁剪质量模型以提高吞吐量。其输入应包含标题、原图和渲染后的候选裁剪图。只有配对的人工判断或经过验证的标签可以作为监督信号。
